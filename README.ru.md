Wickle — движок агентов, который EpsilonDelta разрабатывает на Rust. Цель проекта — предоставить встраиваемую в приложения библиотеку, выполняющую цикл принятия решений моделью и вызовов инструментов.

В основе архитектуры — профили агентов (Agent Profiles) для настройки их поведения и адаптеры для подключения различных моделей и инструментов.

**Статус:** В разработке. Агенты поддерживают последовательные вызовы модели и инструментов, отдельные системные входные данные, сохранение результатов, повторное чтение событий, отмену и продолжение после сохранённого ожидания одобрения, ввода или подтверждения внешнего эффекта. Команды продолжения обрабатываются без дублирования; внешние эффекты подтверждает Host. Хуки жизненного цикла поддерживают ограниченное преобразование контекста и аргументов, а также наблюдение за сохранёнными результатами. Экспорты Tool/Hook/ContextSource адаптеров используют зафиксированную конфигурацию и экземпляры для каждого сегмента; ресурсы освобождаются по его завершении. [Среда адаптеров](docs/adapters.md). Прерванное выполнение можно восстановить с проверкой владельца, сохранением входных данных и сверкой внешних эффектов. [Восстановление](docs/recovery.md). [Запуск агента](docs/agents.md) · [Контракты данных](docs/contracts.md).

[Источники контекста](docs/context-sources.md) с доступом только для чтения поддерживают запросы для Run или шага модели, сохранение данных и проверку текущих прав при повторном использовании.

[Skills](docs/skills.md) загружает полные инструкции фиксированной версии через зарегистрированный инструмент. [Artifacts](docs/artifacts.md) сохраняет оригиналы в пределах scope, ограниченные предпросмотры и сведения об источниках.

[Выбор и сжатие контекста](docs/context-compaction.md) сохраняет исходный диалог и использует ограниченные предпросмотры и проверенные сводки. Сжатие с помощью модели расходует общий бюджет Run.

[Проверка результатов](docs/verification.md) поддерживает схемы JSON, версионированные критерии, ограниченные доработки и одобрение зафиксированного кандидата. Проверки с помощью модели используют общий бюджет Run.

[Адаптер OpenAI Responses](docs/openai.md) поддерживает HTTP/SSE-генерацию с ограничениями, вызовы функций, структурированный вывод и проверку версий моделей с учётными данными приложения.

Развёртывания Azure и аутентификация через ключ API или Entra, управляемая Host, описаны в [руководстве по адаптеру Azure OpenAI](docs/azure-openai.md).

Claude Messages, сохранение подписей thinking и учётные данные workspace описаны в [руководстве по адаптеру Anthropic](docs/anthropic.md).

Подпись AWS, профили вывода и потоковые протоколы описаны в [руководстве по адаптеру Bedrock](docs/bedrock.md).

Версии API, схемы функций и сохранение подписей рассуждений описаны в [руководстве по адаптеру Gemini](docs/gemini.md).
